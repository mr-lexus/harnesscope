# Аудит и переработка Harnesscope

Дата: 3 октября 2026 года. Проверены исходники Rust/React, SQLite, API, wrapper CLI, Git-наблюдение, установщики, CI и интерфейс. Изменения находятся в рабочем дереве; публикация релиза и развёртывание не выполнялись.

Ниже сохранены результаты последовательных этапов аудита. После первоначальной проверки установлен локальный Windows-сборщик; текущие инструкции — [RUNNING.ru.md](RUNNING.ru.md). Последующее код-ревью перед коммитом описано в конце документа.

После исходного аудита добавлен нативный Codex rollout collector: Sources, checkpoint/restart, turns, tool invocations и наблюдаемые токены. Актуальные возможности и границы — в [NATIVE_SOURCES.md](NATIVE_SOURCES.md).

## Основные исправления

| Область | Проблема | Исправление |
| --- | --- | --- |
| HTTP | Wildcard CORS открывал локальную телеметрию сторонним страницам; shutdown принимал cross-origin запросы | Проверки Origin, Host и Sec-Fetch-Site; loopback-only bind; нет wildcard CORS |
| Статические файлы | Путь URL соединялся с `web/dist` в текущем рабочем каталоге, позволял выходить из него | Убран произвольный filesystem fallback, запрещены traversal-пути; неизвестные API возвращают 404 |
| События | Дедупликация только строки события не предотвращала повторные побочные изменения | Проверка ID до проекций в одной транзакции; повтор не открывает завершённое выполнение и не удваивает вызовы |
| Атомарность | Сбой в середине обработки оставлял частично записанную модель | Транзакция на всё событие с rollback, включая ошибки и раскрутку стека |
| Миграции | DDL и запись версии применялись раздельно | Транзакционные миграции и отказ от неизвестной более новой схемы |
| Возобновление | Новый локальный ID обёртки создавал отдельное выполнение вне уже найденной нативной сессии | Постоянная таблица aliases и канонизация последующих событий |
| Неизвестные IDs | Общие `sess_unknown`/`run_unknown` объединяли независимые записи | Отдельные ID для неизвестных сущностей; валидация IDs ключевых событий |
| Lineage | Неимпортированный родитель нарушал FK и терял дочернюю сессию | Сессия сохраняется; неподтверждённый parent остаётся в payload |
| API ingestion | Ошибки скрывались за 202 | Валидация всего пакета, 422 с точными ID неуспешных событий, успешные ID для повтора |
| Секреты | Regex по сериализованному JSON пропускал вложенные поля и мог ломать escaped значения; title не очищался | Рекурсивная обработка JSON до проекций; дополнительные patterns; config contents только при opt-in |
| Статистика | JOIN умножал resume_count; текстовое сравнение времени смешивало RFC3339 и SQLite datetime | DISTINCT для resume bindings, сравнение через julianday; безопасный offset больших страниц |
| Git | trim сдвигал первый символ porcelain; пробелы, Unicode и renames разбирались неверно | NUL-разделённый porcelain v1, корректный rename; staged diff включён при наличии HEAD |
| Attribution | Поздний snapshot мог снова показать OBSERVED при AMBIGUOUS execution | Атрибуция задаётся сервером и распространяется на снимки |
| Wrapper | Blocking HTTP запускался внутри async runtime; автозапуск использовал всегда порт 4242 | Blocking wrapper перенесён в blocking worker; используется настроенный порт |
| Windows autostart | Фоновый сервер наследовал каналы вывода и блокировал захват результата CLI | Запуск через CreateProcessW без наследования handles, без окна; отдельный сквозной тест |
| Процессы | PID обозначал wrapper, завершённые агенты оставались RUNNING | Фактический child PID; завершение агентных записей и bindings; неполные executions становятся UNKNOWN |
| CLI metadata | `-s` неверно трактовался как session у Codex/Copilot; Codex читал вымышленный config.json | Уточнены проверенные аргументы, resume/fork и config.toml; generic CLI не интерпретирует чужие флаги |
| UI | Процесс назывался turn; Runner содержал константу CLI; нулевая длительность показывалась как незавершённость | Явная область наблюдения, исправленные подписи и нулевые длительности, актуальный номер версии |
| Установка | Архивы распаковывались без проверки контрольных сумм; при ошибке latest выбирался старый релиз | SHA-256 перед распаковкой, fail closed, уникальный временный каталог и безопасная очистка |
| Release workflow | Версия workflow_dispatch подставлялась непосредственно в shell | Передача через env и проверка допустимого формата |

## Новое продуктовое ядро

Overview и review-форма связывают наблюдение с человеческой оценкой результата, позволяют группировать эксперименты и экспортировать отфильтрованную ретроспективу. Общий JSON/JSONL-import открывает интеграцию с любым агентом через документированный контракт. См. [направление продукта](PRODUCT.ru.md), [API событий](EVENTS.md) и [исполняемый пример](../examples/events.jsonl).

## Проверки

- Сборка TypeScript/Vite и Rust.
- **64 Rust-теста прошли** (12 unit + 13 regression + 5 CLI + 6 delivery + 16 integration + 12 native source), включая реальный CLI → локальный HTTP → SQLite на отдельном порту и с временной БД.
- Инъекция сбоя SQL для проверки rollback, миграция v2 → v5, повторная доставка, session aliases после пересоздания engine, счётчики и фильтры времени.
- HTTP-проверки hostile Origin/Host, traversal, неизвестных API, частичных ошибок и проверки входных событий до записи.
- Clippy с запретом предупреждений и rustfmt; проверки добавлены в CI для Windows, Linux и macOS.
- `cargo audit` и `npm audit`: известных уязвимостей не найдено; удалена yanked-версия транзитивного `yoke-derive` из lockfile.
- Проверка UI в браузере на отдельной локальной БД: пустое состояние, demo exclusion, обзор с данными, сохранение review, обновление групп, фильтры в URL, экспорт без ошибок браузера и узкий экран 390 px без горизонтального переполнения. PowerShell installer проверен синтаксическим парсером; скачивание/установка реального релиза не выполнялись.

Локальная среда проверки — Windows. Linux/macOS представлены в CI; результаты удалённого CI в этой задаче не запускались и не заявляются как пройденные.

## Честные границы текущей версии

- Обёртки наблюдают запуск процесса, не его внутренние turns. Они не перехватывают stdout и не распознают все внутренние события IDE. Для Codex добавлен нативный rollout adapter с явными границами поддерживаемого формата. Общий `ingest` по-прежнему принимает наш формат, а не произвольные журналы.
- Завершение GUI-launcher не доказывает завершение редактора. Внутреннее изменение cwd агентом тоже не доказывается снимком launch directory. Git attribution означает наблюдение, не авторство изменений.
- Метаданные аргументов/config не доказывают фактически обслужившую запрос модель. Переключение модели внутри интерактивного процесса не наблюдается wrapper-ом.
- Wrapper имеет durable outbox и heartbeat каждые 15 секунд; Monitor отделяет свежесть наблюдения от результата. RUNNING означает отсутствие записи завершения. Упавший wrapper/агент автоматически не перезапускается; ограничения очереди и восстановления описаны в [DELIVERY.md](DELIVERY.md).
- События надо подавать в причинном порядке. Поздняя реконструкция неизвестного parent, расчёт стоимости, OTLP и журналы других агентов остаются следующими этапами. Наблюдаемые token counters Codex уже поддерживаются.
- Нет гарантии абсолютного удаления всех секретов: redact — best effort. База, пути, prompts и заметки всё равно могут содержать чувствительные сведения. Старые записи не переписываются автоматически.
- Нет серверной аутентификации для недоверенных локальных пользователей. Сетевое размещение намеренно запрещено.
- SQLite использует одно соединение; отдельные старые read-handlers синхронные. Для больших архивов потребуются load-тесты, read connections, пагинация подробных timelines и retention. Измерения на больших реальных базах ещё не проводились.
- Обновление схемы сохраняет существующие записи с `capture_scope=UNKNOWN`; оно не исправляет задним числом неправильно связанные исторические данные. Перед обновлением существующей важной БД нужен backup. Демо-записи из старой версии автоматически не переклассифицируются.

Аудит устраняет воспроизведённые проблемы и добавляет защиту от регрессий; он не является доказательством отсутствия любых будущих ошибок.


## Проверки нативного сборщика

Повторный импорт и копия файла без дублей; реальные stop/restart сервера; незаконченная UTF-8 строка; изменённый/усечённый файл; частичный сбой среди нескольких файлов; SQL rollback с checkpoint; устаревший checkpoint второго сборщика; отмена сканирования, ограниченный backlog, пауза/возобновление/удаление регистрации; токены fork/reset; metadata-only и opt-in redaction; отсутствие ложного конфликта с wrapper-ом. В браузере проверены подключение источника, пауза/возобновление, token cards и узкий экран Sources без переполнения. Проверки использовали синтетические rollout fixtures и отдельные тестовые базы, не личную историю пользователя.


## Доставка и компактная панель

Дисковая очередь до HTTP, повтор после потерянного ack, lease/CAS для конкурирующих потребителей, порядок внутри runtime, независимые streams, сохранённый backoff, редактирование payload до записи. Реальный CLI-тест: offline run с exit 7 → новый сервер → завершённая доставка без запуска нового wrapper. Реальный длительный child подтверждает периодические heartbeat и прекращение наблюдений после выхода. Проверены rollback пачки, устаревшие сигналы и невозможность повторно открыть завершённый процесс.

Интерфейс: мобильные карточки запусков/сессий/экспериментов, компактная навигация, плотность отображения, пауза polling, URL-фильтры, пагинация сессий, раскрываемая диагностика, drawer подключения источника, поиск событий, отложенная загрузка страниц. Прежний список сессий не давал открыть записи за первой страницей; это исправлено. Пауза интерфейса не останавливает сборщик.

Визуально проверены ширины 320, 390, 768, 1024 и 1440 px: основные разделы не расширяют документ по горизонтали; широкие таблицы и вкладки прокручиваются внутри своих областей. В браузере проверены сохранение оценки, сохранность черновика при смене вкладок, поиск событий, возврат к URL-фильтру, открытие/закрытие формы источника, сохранение плотности после перезагрузки, пауза/возобновление polling и Monitor с завершённым реальным тестовым процессом. Ошибок в console не обнаружено. Тестовые записи находятся в отдельной preview-БД.

## Код-ревью перед коммитом — 2026-10-03

Повторно проверены транзакции проекций и checkpoint, идемпотентность нативных событий, outbox/backup, завершение фонового процесса, локальный установщик, API и формы панели. Точечные исправления:

- Повторный `session_meta` того же thread больше не сбрасывает базу legacy token counters: иначе следующий накопительный sample мог повторно начислить уже учтённые токены. Проверка воспроизводит повтор после сохранения checkpoint и открытия базы заново. Смена thread внутри файла по-прежнему отклоняется.
- Неизменившийся файл с незаконченной последней строкой (`WAITING`) пропускается до изменения размера/mtime, как уже было для `READY`. Это убирает повторное хеширование всего прочитанного префикса на каждом опросе. После дописывания проверка префикса и обработка возобновляются; тест проверяет частично записанный UTF-8.
- Число ошибочных файлов считается SQL-агрегатом, без повторного чтения всех parser checkpoints в конце каждого прохода.
- `server start` возвращает ненулевой код при недоступности запущенного сервера. Сквозной тест удерживает порт чужим TCP-listener и проверяет отказ.
- Windows-установщик ждёт освобождения EXE при обновлении: закрытие HTTP listener может произойти раньше завершения текущего пакета сборщика. Повтор копирования ограничен 30 секундами и ошибками блокировки/доступа Windows; остальные ошибки немедленно возвращаются.
- В `.gitignore` добавлены файлы outbox SQLite и журналы, чтобы локальная очередь не попадала в коммит.

Новых миграций и изменения пользовательской политики содержимого в этом ревью нет. Старые смешанные fork-rollout остаются явно неподдерживаемыми; исходные логи не переписываются. Оптимизация WAITING использует тот же контракт размера/mtime, что и READY, и не обещает обнаружить намеренную замену файла с сохранением обоих атрибутов.
Проверки этого этапа: `cargo test --release --all-targets --locked -j 1` — 77 тестов прошли; `cargo clippy --release --all-targets --locked -j 1 -- -D warnings`, `cargo fmt --all -- --check`, frontend production build, `cargo audit`, `npm audit --audit-level=high` — успешно. Синтаксис установщика проверен PowerShell-парсером, выполнено настоящее обновление локальной установки с проверенным backup; хеш установленного EXE совпадает с проверенной сборкой. После обновления очередь нативного импорта пуста, сохраняются только три ранее выявленных несовместимых файла. Удалённый CI проверяется отдельно после push.
