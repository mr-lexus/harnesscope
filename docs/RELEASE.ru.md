# Harnesscope v0.3.0-rc.2

[Документация](../README.ru.md#документация)

**Предварительный выпуск для проверки в работе.** Приёмка настоящего Codex GUI на macOS, проверка ответов подключённых трекеров и недельная ретроспектива ещё не завершены. Кандидат не заменяет стабильную v0.2.3 в Homebrew и стандартных скриптах установки. См. [возможности](CAPABILITIES.ru.md) и [сценарии приёмки](ACCEPTANCE.ru.md).

## Изменения относительно v0.2.3

- Локальные оценки и сравнение результатов, явное разделение процессов/turns, компактная адаптивная панель, диагностика источников и мониторинг процессов.
- Возобновляемый сбор истории Codex, наблюдаемые токены и границы fork; очищенный архив с происхождением и явными исключениями. Поддержка JSONL/gzip и выбранной SQLite-истории только на чтение.
- Офлайн-очередь hooks и локальный OTLP/HTTP JSON; версии и различия workflow; хронология задач, человеческие отметки и универсальные конфигурации наблюдаемых MCP-вызовов трекеров.
- Постраничные API наблюдений, read-only MCP через stdio, переносимые экспорт/импорт и переиндексация архива.
- Надёжная доставка обёрток, безопасные повторы событий и checkpoints, проверенный backup/restore со связанными объектами и автоматическая копия перед миграцией.
- Бинарный cask macOS без локальной сборки и обновления Xcode. Стабильный tap по-прежнему устанавливает v0.2.3; кандидат скачивается отдельно.
- Полные пары английских и русских руководств со ссылками на выбранном языке, включённые в архивы с бинарниками.

## Установка кандидата

Скачайте архив для своей платформы со [страницы выпуска](https://github.com/mr-lexus/harnesscope/releases/tag/v0.3.0-rc.2) и перед распаковкой сравните его SHA-256 с `checksums.txt`:

| Платформа | Обозначение в имени архива |
| --- | --- |
| macOS Apple Silicon | `aarch64-apple-darwin` |
| macOS Intel | `x86_64-apple-darwin` |
| Windows x64 | `x86_64-pc-windows-msvc` |
| Linux x64 | `x86_64-unknown-linux-gnu` |

Бинарник самодостаточен: Rust, Node и Xcode для запуска не нужны. `harnesscope --version` должен показать `0.3.0-rc.2`. Для отдельной проверки задайте `HARNESSCOPE_DB_PATH` с новым путём БД и `HARNESSCOPE_SERVER_PORT` со свободным портом в окружении сервера и capture setup. Следуйте [инструкции подключения](EVIDENCE.ru.md). Hooks требуют штатного доверия Codex; необязательный установщик LaunchAgent для macOS требует Python 3 и ещё не прошёл приёмку на настоящем устройстве.

Перед обновлением существующего сборщика создайте и проверьте [резервную копию](BACKUPS.ru.md), завершите доставку очередей и остановите старый процесс. Кандидат использует схему 7 и создаёт копию перед миграцией v5/v6. Не запускайте старый бинарник с обновлённой БД; для отката используйте проверенную копию до обновления в отдельном пути. Очереди и исходные логи агентов хранятся отдельно от backup БД.

## Известные ограничения

Не гарантируется точная реконструкция запроса модели, скрытых промптов и токенов по ролям. Очистка секретов консервативная, best effort, без гарантии для произвольного текста. Нет автоматической перезаписи workflow, скилла анализа, синхронизации машин и встроенных учётных данных трекера. Успешный CI и проверка запуска бинарника не заменяют приёмку GUI. Подробности — в [матрице поддержки](CAPABILITIES.ru.md).
