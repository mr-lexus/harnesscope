# Возможности сбора и статус приёмки

[Документация](../README.ru.md#документация)

Основная матрица поддержки данных для ретроспективы: схема БД 7, формат наблюдений/пакетов 1. Успешный CI на платформе **не подтверждает** полноту сбора из настоящего Codex GUI. Скилл-анализатор ретроспективы здесь не поставляется.

## Платформы

| Агент / платформа | Реализованные каналы | Проверка и рекомендации |
| --- | --- | --- |
| Codex GUI, macOS | Локальная история JSONL/gzip, выбранная история SQLite, поддерживаемые hooks, OTLP/HTTP JSON, пользовательский LaunchAgent | Основная платформа. Приёмка настоящего GUI **ожидается**; полное покрытие пока не заявляется. |
| Codex CLI, macOS/Linux/Windows | Те же локальные каналы и существующая CLI-обёртка | Синтетические контрактные и интеграционные тесты; сквозная приёмка глубокого сбора **ожидается**. |
| Codex GUI, Windows | Нативная история и те же локальные входы сбора | Прежний сборщик метаданных проверен на настоящей локальной истории. Новый сбор содержимого проверен синтетическими фикстурами, не неделей рабочей эксплуатации. |
| Движок Codex GUI 0.153.4; отдельно установленный CLI 0.144.1 | Структуры изучены при планировании | Изучение не равно приёмке. Версия GUI берётся из метаданных источника, а не CLI в PATH. Ни один из них не используется для миграции хранилища Codex. |
| Другие версии Codex | Неизвестные записи можно сохранить после очистки | Неподдерживаемые схемы/границы дают диагностику; общей гарантии совместимости нет. |
| Copilot, OpenCode и другие агенты | Существующие обёртки и `/api/v1/events` | Наблюдения процессов, конфигурации и Git в документированных пределах. Равная глубина нативного сбора не заявляется. |
| Удалённое выполнение | Сбор на хосте выполнения; переносимые пакеты | Не предполагается, что история desktop содержит всё с удалённого хоста. Автоматической синхронизации машин нет. |

## Что собирается

- Очищенные JSON-записи с исходной структурой: доступные пользовательские/developer/базовые инструкции, сообщения, вызовы/результаты инструментов, контекстные события, compaction/replacement history, `world_state`, нативный usage и неизвестные типы. Исходные файлы не переписываются. Сбор содержимого включается явно; Sources позволяет повторно прочитать оригиналы.
- Происхождение: канал, источник, позиция, версия движка при её наличии, нативные ID сессии/turn/item, время источника и получения, результат/причина очистки, версии форматов. Отсутствующие ID не выдумываются; время сбора не равно времени запроса модели.
- Legacy `response_item` и paginated `item_completed` используют нативные ID вызовов для существующей статистики. Дополнительные SQLite/hooks/OTel не увеличивают эти счётчики: записи архива сохраняются как отдельные доказательства, а не дополнительные turns.
- SQLite: явная регистрация `.sqlite` читает только известные столбцы `thread_items`: `rowid`, `thread_id`, `turn_id`, `item_id`, `updated_at_ordinal`, `item_json`. Базы Codex не копируются; таблицы авторизации/регистрации и миграции не затрагиваются. Обновления обнаруживаются периодическими ограниченными проходами.
- Hook очищает stdin до записи в офлайн-очередь. В stdout не выдаются инструкции; даже при ошибке сбора команда завершается успешно с общей диагностикой в stderr. Сервер независимо обрабатывает очередь.
- OTel: `/v1/logs` и `/v1/traces` принимают **OTLP JSON**, до 2 MiB / 500 записей в HTTP-пакете. Задайте `protocol = "json"`. Protobuf, gRPC, сжатые HTTP-тела и метрики не поддерживаются.
- Workflow: только явно зарегистрированные корни и узкий список файлов — AGENTS/CLAUDE/GEMINI/WORKFLOW/SKILL Markdown, каталоги скиллов/инструкций, выбранные TOML-конфиги и package scripts. Изменение создаёт версию, одинаковое содержимое — нет. Статус `discovered` не доказывает загрузку или вызов: для этого нужны отдельные нативные наблюдения.
- Трекеры задач: локальная конфигурация выбирает точное имя MCP-инструмента и ID задачи в аргументах/декодированном результате через JSON Pointer. Совпадающие нативные call ID и сессия связывают версию ответа с задачей в пространстве имён. Нет встроенных провайдеров, учётных данных и фоновых запросов. Неизвестные структуры остаются в архиве; актуальность задачи не выдумывается. См. [адаптеры задач](TASK_ADAPTERS.ru.md).
- Человеческие отметки: принято, переделка, повторная ошибка, неверно понята задача, удачный подход. Одна задача может объединять несколько сессий/turns. Упоминание ID не подтверждает связь автоматически. Git/тесты/CI/review доступны из наблюдаемых инструментов или нормализованных событий; самостоятельных запросов к GitHub нет.

## Границы приватности

Известные секретные поля, присваивания, заголовки авторизации и распространённые форматы ключей очищаются **до сохранения**. Ссылки на секретные файлы (`.env`, хранилища авторизации, SSH/приватные ключи), карты окружения, зашифрованное и непрозрачное бинарное содержимое вызывают исключение содержимого с сохранением причины. Вызов чтения известного секретного файла исключает и связанный JSONL-результат. Непарные SQLite-результаты и фрагменты результатов OTel исключаются: их входные данные нельзя проверить.

Это консервативная очистка best effort, **не доказательство отсутствия любых секретов в произвольном тексте**. Неизвестные кодировки, собственные форматы ключей, косвенный/отложенный вывод и преобразования источника могут обойти детектор. Не включайте секреты в промпты и вывод агента. Исходные файлы Codex находятся вне контроля Harnesscope. Консервативная политика может исключить и безопасное содержимое. Неограниченного raw-режима нет.

## Хранение и надёжность

- Перед миграцией v5/v6 создаётся проверенная резервная копия. События и оценки сохраняются; checkpoints v5 сбрасываются для наполнения архива из доступных оригиналов. v6 → v7 добавляет локальные конфигурации задач без сброса сборщиков и удаления задач.
- Малые объекты хранятся в SQLite. Объекты больше 64 KiB — в `<database>.objects` под именами SHA-256. Надёжная запись предшествует ссылке в БД и commit checkpoint. Rollback может оставить очищенные файлы без ссылок. Чтение и backup проверяют хеши. Автоматического удаления истории нет.
- Размещение определяется `HARNESSCOPE_DB_PATH`; выберите том до начала сбора. Отдельного перемещения каталога архива через UI пока нет.
- JSONL читается потоком без лимита 256 MiB на файл; остаётся 32 MiB на запись. Пакет: до 200 записей / примерно 8 MiB, одна более крупная запись допустима. Поддерживается gzip JSONL; другое сжатие — нет. Проверка префикса и возобновление gzip могут перечитывать предыдущие байты: очень большие активные файлы требуют больше I/O, постоянное время поиска не гарантируется.
- При нехватке места запись объектов/очереди приостанавливается с резервом 128 MiB. Ошибки БД сохраняют checkpoints или очередь hooks. Это не общая квота диска и не гарантия сохранения каждого hook при заполненном диске.
- Backup встраивает связанные внешние объекты в переносимый снимок SQLite. Restore проверяет их, создаёт новый путь и приостанавливает нативные источники. Ожидающие wrapper outbox и hook queue в backup не входят.
- Экспорт читает отдельный снимок SQLite, последовательно пишет JSONL и фиксирует выборку, границу и версии форматов. Контекст workflow/задач включён. Импорт повторно очищает данные, допускает повтор и не включает импортированные корни workflow. Ошибочный пакет может оставить уже принятую начальную часть; повтор идемпотентен. Существующие идентичности/связи задач не перезаписываются.

## Явные пробелы и условия готовности

Недоступны скрытые системные промпты, внутренние рассуждения, полные точные запросы модели, надёжная разбивка токенов по ролям и уже усечённые Codex данные. Накопленный usage не обозначается как текущий активный контекст. Неизвестные и оценочные значения нельзя превращать в нули. Удалённую историю повторным импортом не восстановить.

Для полной приёмки ещё нужны:

1. Реальные сценарии macOS GUI и CLI: уточнение, ошибка/исправление, compaction, resume, fork, подагенты; версии движка/ОС и очищенная фикстура каждого сценария.
2. Три настоящих legacy fork-файла Windows уже достигают READY: 200, 241 и 238 строк. Проверить аналогичные форматы macOS: явные метаданные родителя и нативный `started_at` отделяют унаследованный префикс. Неоднозначные/отсутствующие границы не означают полное покрытие.
3. Проверить реальные MCP-ответы каждого подключённого трекера и версии задач/комментариев. Синтетические тесты не сертифицируют ответы частного провайдера.
4. Снимки workflow основаны на опросе. Отсутствующие/запрещённые файлы создают версии исключения, но изменения короче интервала можно пропустить. Фактическую загрузку и вызов инструкций подтверждают нативные данные.
5. Более подробная атрибуция кода и представления approvals/запросов остаются будущей работой. Страницы контекста показывают наблюдаемые окно/usage и недоступность активного заполнения; нативные родительские связи сохраняются. Другие таблицы SQLite не читаются.
6. Нагрузочные и аварийные проверки многогигабайтных активных rollouts, остановки при записи объекта, нехватки диска и всех новых платформенных установщиков.
7. Восстановить несколько настоящих задач за неделю и объяснить каждый пробел.

Будущий анализатор уже может использовать API/MCP для разработки, но **приёмка готовности к рабочему скиллу остаётся открытой** до прохождения этих проверок.
