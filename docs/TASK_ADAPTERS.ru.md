# Подключение трекера задач через наблюдаемые MCP-вызовы

[Документация](../README.ru.md#документация)

В Harnesscope нет встроенного провайдера трекера. Подключите MCP трекера к агенту с его собственной авторизацией. Harnesscope наблюдает захваченные вызовы/результаты агента: не подключается к трекеру, не опрашивает задачи, не устанавливает MCP-сервер и не хранит учётные данные провайдера.

## Локальная конфигурация

Скопируйте [универсальный пример](../examples/task-adapter.json) в `task-adapters.local/read-task.json` (исключён из Git). Замените имя инструмента и пути полей на присутствующие в очищенном наблюдении:

```json
{
  "schema_version": 1,
  "id": "tracker-read-task",
  "namespace": "team-tracker",
  "tool": "mcp__tracker__get_task",
  "task_id": { "source": "arguments", "pointer": "/taskId" },
  "title_pointer": "/title"
}
```

```sh
harnesscope task-adapters add task-adapters.local/read-task.json
harnesscope task-adapters list
# Необязательно: построить связи из уже сохранённых наблюдений.
harnesscope evidence reindex
# Отключить новые связи, сохранив историю и человеческие отметки.
harnesscope task-adapters remove tracker-read-task
```

Используйте тот же `HARNESSCOPE_DB_PATH`, что у сборщика. Регистрация хранится в БД и действует без перезапуска. По умолчанию адаптеры выключены. Лимит файла конфигурации — 16 KiB. Неизвестные поля, небезопасное содержимое, неверные указатели и неподдерживаемые версии отклоняются; секреты в этот файл не помещайте.

## Контракт конфигурации, версия 1

| Поле | Значение |
| --- | --- |
| `id` | Неизменяемое локальное имя: 1–80 ASCII-букв, цифр, `.`, `_`, `-`. |
| `namespace` | Область трекера/аккаунта/workspace с тем же синтаксисом. Разным областям нужны разные пространства имён. Несколько инструментов одного трекера могут использовать общее. |
| `tool` | Точное наблюдаемое имя с учётом регистра. Без поиска подстрок и масок. Только одна активная конфигурация на инструмент. |
| `task_id.source` | `arguments` или `result`. |
| `task_id.pointer` | RFC 6901 JSON Pointer к одному стабильному ID: вложенные поля, индексы массива, `~1` для `/`, `~0` для `~`. Пустая строка выбирает корень. |
| `title_pointer` | Необязательный указатель в декодированном результате на отображаемое название. При отсутствии используется ID с пространством имён. |

Аргументы могут быть объектом или JSON-строкой. Результат — обычный JSON, JSON-строка, MCP `structuredContent` или единственный текстовый блок MCP с JSON/текстом. Указатели результата применяются **после** декодирования оболочки. Для `structuredContent: {task: {id: 42, title: "Fix tests"}}` используйте `task_id: {source: "result", pointer: "/task/id"}` и `title_pointer: "/task/title"`. Допустимы строковые и целочисленные ID; очищенные, отсутствующие и составные ID отклоняются.

Идентичность задачи: `mcp:<namespace>:<native-id>`. Вызов и ответ должны иметь одинаковые нативный call ID и сессию; разные известные turn ID несовместимы. Рассматривается только последний совпадающий вызов, даже если он относится к незарегистрированному инструменту. Известные ошибочные результаты не становятся версиями задач. Post-tool hook с именем инструмента, аргументами, call ID и ответом содержит обе стороны в одном наблюдении: отдельная pre-tool запись не нужна. Используйте инструменты чтения задач: Harnesscope не определяет смысл успешности произвольного ответа и не проверяет актуальность задачи у провайдера.

Каждый ответ сохраняет наблюдение, хеш объекта и время получения. Изменённые требования/комментарии остаются отдельными версиями. Повторная доставка того же наблюдения и reindex не дублируют версии. Полный очищенный ответ доступен; конфигурация извлекает только идентичность и начальное название, не сокращая содержимое. В списке задач показывается первое наблюдаемое название; последующие остаются в версиях.

## Ограничения и жизненный цикл

- Одна задача на результат. Для списка/пакета используйте чтение одной задачи либо частный промежуточный инструмент с одной задачей на вызов. Фиксированный индекс массива выбирает один элемент, не перебирает список.
- Без захваченного вызова, стабильного ID, безопасного содержимого или известной оболочки результат остаётся обычным наблюдением. Упоминания в тексте не подтверждают связи.
- Конфигурация не восстановит отсутствующую телеметрию. Сначала включите очищенное содержимое. Поддерживаются нативный `response_item`, элементы payload в `item_completed`, hook-записи `tool_input`/`tool_response`.
- Иная конфигурация под существующим ID отклоняется. Для смены трактовки отключите старую и создайте новый ID. Исторические связи и версии сохраняются; reindex добавляет новые поддержанные связи, не переписывает прежнюю идентичность и оценки молча.
- SQLite backup/restore включает конфигурации. Переносимые пакеты включают данные задач и связи, но не устанавливают конфигурацию адаптера на другом хосте.
- Частные имена инструментов могут попасть в локальные наблюдения и экспорт. Перед передачей проверьте пакет: исключение конфигурации из Git не делает собранное содержимое безопасным для публикации.

Проверяйте на вымышленных задачах: чтение → изменение требований/комментариев → повторное чтение → две версии → перезапуск/reindex без изменения счётчиков. Также проверьте ошибочный ответ и одинаковые ID в двух пространствах имён. См. [приёмку](ACCEPTANCE.ru.md).
