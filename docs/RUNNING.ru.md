# Ежедневное использование Harnesscope

[Документация](../README.ru.md#документация)

> Документ описывает этап работы от 3 октября 2026 года; статусы и планы ниже относятся к тому этапу. Актуальные возможности и открытые проверки — в [матрице поддержки](CAPABILITIES.ru.md).

## На этом компьютере

Рабочая панель: **http://127.0.0.1:4242/**. Порт 4343 использовался только для тестовой панели.

Откройте **Harnesscope** через меню «Пуск». Приложение запустит локальный сервер при необходимости и откроет панель. Терминал, Node.js и Rust для установленной сборки не нужны.

Сборщик подключается к каталогу `sessions` выбранной установки Codex. Существующие файлы импортируются постепенно; новые файлы и дописанные строки подхватываются автоматически. Можно закрыть браузер и продолжать работать в Codex. Запись данных продолжится, пока работает сервер.

На этой Windows-установке включён запуск при входе пользователя. До входа в систему сервер не работает; после входа продолжает с сохранённых позиций. Это пользовательская фоновая программа, а не системная служба или watchdog. После аварийного завершения откройте Harnesscope через «Пуск»; сохранённые исходные логи позволяют догрузить пропущенное.

## Что собирается

- Идентификаторы сессий и turns, начало/завершение, наблюдаемые модель и reasoning effort.
- Вызовы инструментов, представленные поддерживаемыми записями rollout.
- Доступные счётчики токенов. При наличии новых per-turn-счётчиков они имеют приоритет над старым `token_count`: складывать два формата нельзя.
- Исходный рабочий каталог и связи, которые можно установить по явным данным.

По умолчанию тексты сообщений, инструкции, reasoning, аргументы и результаты инструментов **не сохраняются**. Исходные файлы не изменяются. Хранилище и HTTP-сервер локальные; модельные API для сбора не вызываются. Метаданные, например пути и названия инструментов, тоже могут быть чувствительными.

## Управление

В **Sources** видны состояние, последний проход, количество файлов, отставание и ошибки. **Pause** приостанавливает источник с сохранением позиции; **Resume** продолжает его. Закрытие вкладки и кнопка Pause automatic refresh влияют только на отображение, а не на сборщик.

Ярлык **Harnesscope - stop collection** в «Пуск» останавливает весь сервер. Следующий запуск Harnesscope или следующий вход в Windows снова запустит сервер. Чтобы надолго остановить конкретный источник, используйте Pause в Sources.

Автозапуск хранится в пользовательской папке Startup как `Harnesscope Collector.lnk`. Открыть её можно командой `shell:startup` в окне «Выполнить». Удаление только этого ярлыка отключает запуск при входе и не удаляет базу. Установщик с `-AutoStart` создаёт его заново.

Программа: `%LOCALAPPDATA%\Programs\harnesscope\bin\harnesscope.exe`.
База: `%LOCALAPPDATA%\harnesscope\harnesscope\data\harnesscope.db`.
Перед обновлением локальный установщик сохраняет проверенную копию существующей базы в подкаталог `backups`. Дополнительные копии: [BACKUPS.ru.md](BACKUPS.ru.md).

## Ошибки старого формата

Ошибка одного файла не останавливает импорт остальных. Раскройте **File checkpoints and diagnostics**: проблемные файлы показываются первыми. Не редактируйте исходные логи только ради зелёного индикатора.

При проверке настоящего архива 2026-10-03 найдены три старых fork-rollout, содержащих метаданные дочерней ветки, затем скопированную историю родителя. Такой смешанный формат пока отклоняется: иначе можно приписать работу родителя дочерней сессии и удвоить статистику. Новые обычные rollouts продолжают собираться. Наличие завершения/токенов без наблюдаемого начала turn также не создаёт выдуманное выполнение; такая запись остаётся unmapped.

Статус RUNNING у исторического turn означает отсутствие записанного завершения. Он не доказывает, что процесс сейчас работает. Для наблюдения процесса используется отдельная универсальная обёртка и страница Monitor.

## Повторная установка из исходников (Windows)

```powershell
cd web
npm ci
npm run build
cd ..
cargo build --release -j 1
.\scripts\install-local.ps1 -AutoStart
```

Установщик использует `CODEX_HOME\sessions`, если задан `CODEX_HOME`, иначе пользовательский `.codex\sessions`. Можно передать `-CodexPath 'D:\Codex\sessions'`, `-Port 4242`, `-InstallDir` и `-DataDir`. Режим сбора — метаданные. Если источник уже зарегистрирован с иной политикой содержимого, установщик останавливается, а не меняет её молча.

Администратор, загрузки бинарников из сети и изменение PowerShell execution policy не нужны. Для скрытого запуска используются локальные VBS-лаунчеры и WScript. Если WScript запрещён политикой организации или недоступен в будущей Windows, используйте `harnesscope serve` в терминале и настройте разрешённый вашей системой способ автозапуска.

Linux/macOS поддерживают `sources add-codex` и `serve`; встроенный установщик автозапуска этого этапа предназначен для Windows. SIGTERM на Unix завершает сборщик с ожиданием текущего ограниченного пакета.
